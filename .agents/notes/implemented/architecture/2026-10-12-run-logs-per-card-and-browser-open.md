# Agent Note: 每条运行的日志独立成块、按需取，日志里的地址交给默认浏览器

Status: implemented

## Problem

运行页原来只有**一个**共享日志面板（`activeId` + 一份 `logText`）：点任意卡片的「日志」都会把这一份缓冲换掉，
两个服务同时跑时，看 A 的日志就等于关掉 B 的；日志块还挂在列表**下方**，跟产生它的卡片对不上号。

日志同时是**全量轮询**的：`GET /status` 每次都把每个实例最多 20 万字符的内存尾部一起回传，2 秒一次。
单服务看不出问题；多服务同时跑时，浏览器每 2 秒要收、要 parse、要 diff 几份几十万字符的 JSON。

另外，开发服务启动后打印的第一行往往就是 `http://localhost:5173/` 这类地址，而面板只能让人手抄；
配置里的 `browserUrl` 也从没有人使用过。

## Decision

**日志归卡片所有。** 每张运行卡片（`src/client/components/RunCard.tsx`）自己持有「日志文本 + 绝对偏移 + SSE 连接」，
展开才装载、收起即断开。面板（`RunPanel.tsx`）只持有「哪几张卡展开了」（`openLogs`，按实例 id）与
「最近看过哪条日志」（`focusedId`，AI 排查的默认目标）。

**日志按需取，轮询只回元数据。** 装载顺序固定为「先 `GET /log` 取尾部 → 再从返回的 offset 连 SSE」。
`log` 因此从「快照里总有」变成 `RunSnapshot` 的可选字段：只有显式要全量（AI 排查）时才带。

**地址交给系统默认浏览器。** 日志里识别出的地址渲染成链接，**只有点击才打开**（不自动打开任何东西），
点击走宿主 `POST /openUrl`；`window.open` 只在宿主失败时兜底。卡片上配置了「浏览器地址」或实例已就绪时，
状态行给出同一个入口。

## 契约：日志与打开地址（wire）

| 调用 | 语义 |
|---|---|
| `GET /status?root=&logs=0` | 轮询用：runs 只带状态/退出码/`offset`/`base`，**不带** `log` |
| `GET /status?root=` | 全量（默认）：AI 排查要日志尾部 |
| `GET /log?root=&id=` | 一次性读某实例的内存日志尾部 + 绝对 `offset`；实例不存在回 404 |
| `GET /stream?root=&id=&from=` | SSE：从绝对偏移 `from` 补发，之后持续推增量（原样保留） |
| `POST /openUrl {url}` | 用系统默认浏览器打开；只放行 http(s)；**不回全量快照**（`NO_SNAPSHOT`） |

客户端必须遵守两条：

- 装载顺序是「`/log` 取尾部 → 从该 offset 连 SSE」。中间产生的输出由服务端从 offset 补发，不重不漏。
- **不能用 `EventSource` 自带的重连**：它沿用**建连时**的 `from`，断线期间服务端新增的内容会被再推一遍。
  客户端在 `onerror` 里主动 `close()`，用自己的当前 offset 重连（退避 0.8s×n，最多 5 次，之后靠卡片的「刷新」）。

`src/host/open.js` 里必须保持的三个约束：

- **不走 `ctx.subprocess`**：那条路把子进程收进宿主管理的 Job 容器，宿主退出 / 插件重挂时容器关闭会连带杀掉
  刚打开的浏览器。改用 Node 原生 `spawn(cmd, args, { detached: true, stdio: 'ignore', windowsHide: true })`
  + `unref()`；等到 `spawn` 事件才算发出去，失败要能作为接口错误回到面板。
- **Windows 不用 `cmd /c start`**：`&`、`%` 在 cmd 里是语法，而开发服务打印的地址经常带查询串
  （`http://localhost:3000/?a=1&b=2`），`start` 会把 `&` 后面拆成第二条命令。改用
  `rundll32.exe url.dll,FileProtocolHandler <url>`——单个 argv，没有 shell 二次解释。macOS `open`、Linux `xdg-open`。
- **只放行 http(s)**：入参来自浏览器，放开 `file:` / 自定义协议等于把「执行任意 shell 关联」的能力交出去。

地址识别收窄在 `src/client/urls.js`：`http(s)://` 全地址，以及开发服务常打印的「主机:端口」——
`localhost:5173`、`127.0.0.1:3000`、**任意 IPv4 + 端口**（`192.168.1.5:8080`，内网/Vite Network 那行）、`[::1]:port`，
统统补 `http://` 再当链接。两条**不认**：裸域名（`foo.com` 更可能是文件名或包名）与不带端口的裸 IP
（`1.2.3.4` 无从判断是不是在说一个服务，且容易撞上版本号——IPv4 那一支因此**强制要求端口**）。
`0.0.0.0:8080` 是「监听所有网卡」的通配地址，浏览器连不上，所以只把 **href** 换成回环 `127.0.0.1`，
日志里显示的文字保持原样。句末标点与**不成对**的右括号从地址尾巴上剥掉（`see http://x/a.`、`(http://x/a)`），
成对的保留（`.../wiki/Foo_(bar)`）。链接的显示文本保持日志原文，规范化只用于 `href`。

## Alternatives considered

- **保持一个共享日志面板**（改前状态）：多服务同时跑必然互踩，而且「日志跟产生它的卡片对不上」正是原始诉求。
- **每条运行的日志继续靠 2 秒轮询回传**（改前状态）：实现最省事，但成本随实例数线性增长，且收到的人可能根本没在看。
  按需取把成本压到「展开的那一刻」才发生。
- **折叠时也保持 SSE 订阅**：切回来瞬间有内容，但要为看不见的日志长期占 N 条连接与心跳；重开时
  「`/log` + 从 offset 续读」本来就不会丢内容。
- **`window.open` / `<a target="_blank">` 直接开**：Web 端能开新标签，桌面壳里并不是系统默认浏览器，
  而用户要的正是「调默认浏览器」。
- **`ctx.subprocess` 打开浏览器**：浏览器会进 Job 容器，随宿主退出被带走（见上）。
- **`cmd /c start "" <url>`**：Windows 上最通行的写法，但对带 `&`/`%` 的地址会被 cmd 二次解释——
  日志里的地址恰恰经常带查询串。
- **`@deepseek-ai/dsh-native-command` 的 `openNativePath`**：行为最全（WSL、按文件类型关联），但它不是本插件的依赖，
  从插件的真实路径解析不到（宿主安装目录里的包不在 Node 的解析链上），为一个动作引入依赖不划算。

## Consequences

- 多服务同时跑时，面板不再为看不见的日志付代价；日志块归属明确，各开各的、互不影响。
- 代价：日志不再「快照里就有」，多了一条 `/log` 与一条前端装载顺序的约束；`RunSnapshot.log` 变成可选字段，
  任何新消费者（包括 AI 排查）必须显式走全量 `status`，否则会拿到 `undefined`。
- 代价：SSE 重连从「交给浏览器」变成自己维护（退避 5 次封顶）。
- 代价：`openUrl` 是宿主侧新增的写入口，扩大了浏览器能触发的动作面——用「只放行 http(s) + 同源门禁 + 不回快照」
  把它收窄到「打开一个网页」。
- 验证：`tests/urls.test.js`（地址识别）、`tests/openurl.test.js`（协议门禁 / 平台命令 / 进程脱钩 / 失败上报）、
  `scripts/validate.mjs` 把上述契约钉成断言；真机用独立 `test` profile 同时跑两个实例，验证日志互不串台、
  轮询快照不含日志、`/log` 与 SSE 偏移续读、`openUrl` 拒绝 `file:` 且能真的调起默认浏览器。
