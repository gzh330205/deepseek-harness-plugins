# Agent Note: 「当前」栏目 = 显式注册表（不是时间窗口），以及它的行内动作与状态点

Status: implemented

## Problem

侧栏顶部的「当前」分组最早是按**时间窗口**做的：`updatedAt >= 本地今日 00:00` 的会话，外加正在运行的。
这个定义有两个问题，用户两次明确反馈：

1. **窗口是猜的。** 「今天」只筛掉了一天的量（本机实测：1 天 14 条 / 3 天 16 条 / 7 天 39 条 / 30 天 164 条，
   共 329 条非空白会话）。用户要的是「我正在用/刚跑过的那几条」，而窗口长度无论取几都不对。
2. **「临时移除」是个别扭的机制。** 隐藏写一条 `{at, updatedAt}` 记录，靠「活动戳是否前进」决定何时复活。
   用户明确说了他要的模型：**这一栏就是一份「要显示的会话」配置，隐藏 = 从配置里删掉**。

另外的体验缺口（同一轮反馈）：项目分组标题上没有任何状态标记，看不出哪个组里有会话在跑 / 刚跑完；
行内动作与归档入口的关系也需要定清楚。

## Decision

**「当前」= 显式注册表**，Host Config 字段 `currentSessions`：`会话 id → { at, viewedAt }`。

- **登记只看运行**，两种被观测到的事件：①会话**开始运行**（`running` 由假变真，覆盖自动续跑这类没有
  新提示词的运行）；②它的**活动戳前进**（你发了新提示词，也就是一次新运行）。
  **打开一个会话不登记**（用户明确要求：翻看一下不该让这一栏多出一堆条目）；打开只对**已登记**条目
  刷新 `viewedAt`，用来清掉「跑完了还没看」的加粗标记。
- **隐藏 = 从注册表里 `delete` 掉这条**。于是：从没登记过的历史会话不会自己出现；删掉的也不会自己回来，
  除非它再次运行（那时会重新登记）。分类树、归档、状态聚合完全不受影响。
- **登记是观测型的**：客户端把「上一次看到的会话状态」放在 ref 里（不是配置），只在观察到跃迁时登记。
  重启后 ref 为空 → **首次观测什么都不登记**（没有可比较的跃迁），所以「隐藏过的会话还在跑」不会让它
  自己回来，历史也不会被导入。
- **行内动作只有「定位」和「隐藏」**；**归档不进行内**（会话右键菜单里本来就有 rename / fork / archive，
  行内不放置一个误点代价更高的破坏性动作）。
- **项目分组标题 = 分类栏里的项目行**：同一套类名与结构（`wcm-projectRow` / `wcm-projectLine` / `wcm-projectLabel` /
  `wcm-rowIconSlot` / `.wcm-sessions` + `.wcm-sessionsInner`），会话走同一个 `sessionRow`。原来为这一栏单写的
  `wcm-todayGroup*` 整套（专用标题按钮 + 专用折叠容器 + 专用样式）已删除 —— 两栏是同一种东西，各写一套只会越走越偏。
  分组标题上的状态点是**静态**的（`statusIconSlot(groupStatus, …)` 的角标）：warning > running > done，组内无状态就不渲染；
  「当前」这一行本身不带状态点。
  「当前」这一行**本身不带**状态点（用户决定：运行情况看下面的项目分组标题，那一行当时已有徽标，被要求去掉）。

## 被放弃的方案（以及它们最强的理由）

| 方案 | 最强理由 | 为什么不用 |
|---|---|---|
| 保留时间窗口，只调参数（今天 / 3 天 / 7 天 / 全部） | 零风险、一处常量；参数化后还能让用户自己选 | 窗口永远在猜：用户要的是「跑过的」而不是「最近 N 天的」；而且**看得见、删得掉**比参数更可控 |
| 保留「临时移除记录」（`hiddenToday`），只把窗口去掉 | 已实现，行为已验证（隐藏运行中会话不会弹回） | 用户明确要「隐藏=从配置里删除」；两套真相（注册表 + 抑制名单）会让「谁决定显示」变得含糊 |
| 打开会话也登记（当前会话自动进表） | 点开就看得到，重启后也不空 | 用户明确反对：「不想查看一下多了一堆会话」 |
| 重启后把「最近 N 天有活动的会话」播种进注册表 | 升级后第一眼就有内容，不会空一阵 | 会把用户**故意隐藏过**的会话重新拉回来（旧的 `hiddenToday` 无法区分「没登记」和「曾隐藏」）；也违背「只有刚刚运行的才会配置」 |
| 行内再加一个「归档」按钮 | 一步到位，和隐藏并排 | 用户明确说不用：「归档按钮不用放出来，本身右键支持归档的」 |
| 分组标题用运行动画（`sessionStatusDot`） | 一眼可辨「谁在跑」，比配色更醒目 | 侧栏里会同时有好几个动效；用户明确要求「要是点，而不是运行动画，跟分组中保持一致」 → 最终用静态点 |
| 为「当前」单写一套分组标题样式（`wcm-todayGroup*`） | 可以按需要定制（折叠箭头 + 点 + 名称 + 计数，不背项目行的拖拽 / 菜单包袱） | 与分类栏里的项目行长得不一样，用户直接指出「完全可以按照分类栏下的项目和会话的样式显示」→ 改为复用项目行结构，只保留「不给项目操作按钮」这一条差别 |
| 把分组标题做成「整棵目录一起收起」的容器开关 | 一个按钮收掉全部上下文，实现简单 | 这是本任务的一次误读：用户要的是**分类和项目自身**的折叠/展开，不是把目录藏起来（`validate.mjs` 里留了反向门禁） |

## 契约与落盘格式

`currentSessions`（Host Config，`.volatile()`，可被 DSH 设置系统回落写盘）：

```yaml
currentSessions:
  session-3dbba6d7: { at: 1791775395012, viewedAt: 1791777600000 }
```

- 两个字段都给 `.default(0)` 而不是 `.required()`：客户端写的一定完整，但**手改过的残缺记录不该让整份
  配置校验失败**（默认值下这条记录只是不隐藏/不标记任何东西，下次写入顺带剪掉）。整体 `.default({})`
  让全新 profile 不做任何写入也能校验通过。
- 字段名里的 `today`（`collapsedTodayGroups` / `TODAY_FOLDER_ID`）是历史命名，语义已与「今天」无关。
- 旧的 `hiddenToday` 字段已从 schema 移除并被安全忽略（未知键不报错）：升级后**不会**把以前隐藏过的
  会话重新拉回来（它们只是不在注册表里）。
- 每次写入都过 `pruneCurrentList`：丢掉快照里已不存在的 id，配置不会随使用无限长胖。

## 测试与回归门

`tests/api.test.js` 的「P: 「当前」= 显式注册表」一组断言守着：成员只来自注册表（**历史会话不许出现**，
哪怕它刚刚才活跃过）、分组与排序、子代理/归档/空白/已删会话的排除、隐藏=删除（写盘 + 立刻重绘 + 重启不回来）、
重新运行才回来、登记的三种事件（开始运行 / 活动戳前进 / 打开**不**登记）、以及「跑完了还没看」的加粗与
分组标题的聚合状态点（warning > running > done，无状态不渲染）。

为了让「观测型登记」真的可测，测试里的 React 桩从 `useEffect() {}` 升级为**按依赖比较执行 effect**
（和 React 一致，含 cleanup）——否则核心行为只能靠肉眼验。

`scripts/validate.mjs` 守住结构：注册表字段形状与默认值、`currentRows` 必须从注册表投影、
`registryUpdates` 必须由观测事件驱动、`fresh = startedRunning || advanced`（打开不许成为登记路径）、
隐藏必须是 `delete`、写入必须剪枝、**时间窗口常量与 `hiddenToday` 不许回来**、分组标题必须带聚合状态点、
行内不许出现归档按钮、分组标题不许长出项目操作按钮。

## 已知取舍

- 只看不发的会话不会出现（没有提示词、没有运行，就没有登记事件）；要找它只能用「定位」在分类树里看。
- 隐藏一个**正在运行**的会话，它会一直隐藏到该会话出现新活动为止（运行本身不算新活动）。
- 升级后注册表初为空 ⇒ 「当前」会空到某个会话真的跑起来（这是「只有刚刚运行的才会配置」的直接结果）。
